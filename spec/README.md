# 算法测试说明

核心算法测试维护于本目录，使用 Bun 内置 `bun:test`。网页、API 和其他代码不在这里新增 spec，分别使用类型检查、lint、构建和实际运行验证。

从仓库根目录执行：

```bash
bun run test              # 顶层算法测试
bun run test:all          # ./spec 全部测试，含示例方案
bun run test:scheme       # 独立字库方案与 CLI
bun run typecheck         # 算法源码、测试及脚本类型检查
bun test ./spec/degenerator.spec.ts
bun test ./spec/e2e/examples.spec.ts
```

使用真实字库的测试需要根 `src/data/`；缺少数据时先运行 `bun run fetch`。独立字库用例应覆盖静态/动态分析、条件拆分、构词、简码、自定义元素、配置诊断、CLI 协议、快照复现和结果比较，避免无必要的在线依赖。

通用规则同时覆盖命中例和相似反例，并检查开关两种状态；切片测试调用运行时实际使用的切片生成入口，断言真实字根及笔画索引。字符和字形名称的自定义都需覆盖，具体字形规则优先于字符规则，修正应传播到父级分析。

真实字库回归按当前元数据检查字集范围、来源和笔顺，不用旧快照的固定数量代替来源核验。笔顺差异上限以 `primitive.spec.ts` 为准，超过时报告实际字符及参考笔顺。

示例运行成功仅说明配置和管道可执行，不等于与官方码表完全一致；准确性按根 [校对方法](../AGENTS.md#方案校对与回归方法) 及双向全码集合验收。自定义目标从部件变为复合体、旧字段不再被读取或引用 ID 变化时，先按当前接口检查成因，再修改测试或配置。

已有失败时，用相同代码基线、依赖和数据快照复跑，对照失败条目与类型诊断，明确哪些是新增问题。测试说明保留通用约束和复现方法，不累积具体方案校对战报或易过期的全量计数。
