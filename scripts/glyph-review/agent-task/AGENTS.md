# 字形候选盲选任务

**始终使用中文。此任务由当前会话的子 agent 实际看图完成，不调用外部模型 API。**

## 任务与读取范围

你负责 `assignments/shard-N.json` 分配给你的全部字符及全部非 G 来源。每个任务是一个“字符 × 来源”；根据 Unicode 18.0 的目标字形，从提供的候选中选出正确的一项。

只可读取本盲选目录中的 `AGENTS.md`、你的分片 JSON、`panels/`、`assets/`，以及你自己的 `results/shard-N.json`。禁止读取上级目录、仓库字形/字符数据库、源码、`heldout-private.json`、`truth-private.json`、`baseline-private.json`、`choices-private.json`、其他分片结果或任何统计评分。不得用文件哈希、图像距离算法、训练标签或统计排序代替视觉判断。

## 看图方法

- 必须实际打开每个分配字符的 `panel` 图片。每图最上方是 G 源参考；下面每行左侧是目标来源，右侧是随机排列并标记 A、B、C……的候选。各行的字母独立，不能把上一行的字母当成下一行答案。
- 比较目标与候选的部件结构、笔画增减和连接关系。忽略字体粗细、衬线、字面比例及收笔风格；静态图片不推断笔顺。
- 如果总览图中某个局部不清楚，打开分片 JSON 中对应的 `targetImage` 和候选 `image` 查看原尺寸。
- 用户已经复核裁图并确认可以使用。将切图视为成功；不要因为贴边而暂缓。
- 只按照眼前图片作判断，不根据某地区通常采用的规范字形猜测。每个来源独立判断。
- 如果至少一项匹配，选出最匹配的候选。若候选全部不匹配，输出 `choice: null`，说明缺少什么差异。候选中若存在视觉相同项，可任选一项。
- 不得跳过任务。每个任务都需要具体的简短视觉依据，例如“右下为儿形，A 的两笔与目标一致；B 为几形”。不要统一填写“看起来相同”。

## 输出

将所有结果一次或分批累计写入自己的 `results/shard-N.json`，格式如下：

```json
{
  "reviewer": "子 agent 名称",
  "decisions": [
    { "taskId": "XXXX-J", "choice": "A", "reason": "具体视觉依据" },
    { "taskId": "YYYY-T", "choice": null, "reason": "所有候选均缺少目标右部的一横" }
  ]
}
```

只允许写自己的结果文件。可使用脚本录入和检查任务 ID 是否完整、是否重复；不得通过脚本计算视觉选择。完成后报告实际看过的字符数、完成的来源任务数和结果文件路径；不要尝试计算准确率，评分由父 agent 在盲选完成后单独进行。
